# 学习后归档

本项目的新笔记始终先进入 `00-待整理`。学习后归档默认关闭，只有用户明确提出“整理 / 归档笔记”时才执行。

归档阶段只解决两件事：

1. 这篇笔记应该放到哪里；
2. 文件名怎样更短、更容易识别。

**归档阶段不得修改笔记内容。** H1、Summary、正文、Frontmatter、Tags、视频简介、UP 主资源、`(workbuddy)` / `(GPT)` 等测试标记全部保持原样。

---

## 1. 整理目标

先完整阅读笔记，再做两个判断：放到哪里、文件名怎样更容易长期查找。

> **目录管“它属于谁”，文件名让人一眼知道“这篇能拿来做什么”。**

通常采用：

```text
领域 / 对象 / 笔记.md
```

目录最多两层。有明确模型、工具或项目时，可以围绕它聚合；没有稳定对象时，也可以用主题作为第二层。不要为了套分类而继续细分。

文件名应简短、自然、有区分度。可以删除视频标题里的宣传语和无助于检索的信息，但不要把摘要或章节目录重新塞进文件名。`百科：`、`实测：`、`教程：`、`工作流：`、`对比：` 等写法只在确实更清楚时使用，不是固定模板。

`config/bilibili-note-taxonomy.json` 中的 `routes` 只提供生成阶段的建议路径，不是 Organizer 的强制分类表。

## 3. 整理范围

范围共有三种：

- `single`：用户明确指定某一篇；
- `latest`：用户明确说“最近一篇”；Organizer 会验证它确实是 `00-待整理` 中最近的 Markdown 文件；
- `all`：用户明确要求整理全部待整理笔记；仍逐篇阅读和判断，不把批量整理变成机械套模板。

用户已经明确指定文件时，直接使用 `single`，不要伪装成 `latest`。

只有用户只说“整理笔记”却没有给出对象时，才询问：

```text
要整理指定的一篇、最近一篇，还是全部待整理笔记？
```

## 4. Organizer 命令

统一入口只需要四类信息：原文件、目标文件名、目标目录、已确认范围。

```powershell
bili-learning organize `
  --note '<现有笔记路径>' `
  --filename '<新的简短文件名>' `
  --destination '<领域/对象>' `
  --confirmed-scope '<single|latest|all>'
```

示例：

```powershell
bili-learning organize `
  --note '<...>/00-待整理/Krea-2 百科全书....md' `
  --filename '百科：Krea-2 生图模型全解' `
  --destination '02-图像/Krea2' `
  --confirmed-scope single
```

Organizer 不接受 `--intro`、`--tag`、`--category`，因为归档阶段不再改写简介、Tags 或笔记内部结构。

同名目标已存在时不会覆盖，会自动使用 `（2）`、`（3）` 等序号。

## 5. 内容保护

Organizer 采用移动文件的方式归档，不重新序列化 Markdown 内容。

因此归档前后的文件内容应保持完全一致。唯一允许变化的是：

- 文件路径；
- 文件名；
- 自动生成的 `99-导航` 文件。

这意味着以下内容不会因为归档被二次加工：

```text
H1
Summary
正文
Frontmatter
Tags
视频简介
UP 主资源
原始说明
(workbuddy) / (GPT) 等测试标记
```

如果旧笔记格式需要升级，应由单独的迁移任务处理，不借 Organizer 顺手修改。

---

## 6. 重复 BVID

同一个 BVID 可以存在多个版本，例如不同 Agent / 模型的质量测试。

Organizer 会检测同 BVID 笔记并在返回值的 `duplicate_bvid_notes` 中提示，但：

- 不阻止归档；
- 不覆盖；
- 不自动删除；
- 不自动合并。

如果笔记元信息中带有 `(workbuddy)` 等标记，导航会保留该标记用于区分同标题测试稿。

---

## 7. Junction 路径

当 Obsidian Vault 通过 Windows Junction 指向仓库笔记目录时，同一个文件可能同时表现为逻辑 Vault 路径和真实磁盘路径。

Organizer 返回：

- `note_path`：配置中的逻辑路径；
- `resolved_note_path`：文件系统解析后的真实路径。

例如 `M:` 和 `G:` 同时出现并不代表重复写入。

---

## 8. 不做什么

学习后归档明确不负责：

- 优化正文；
- 重写摘要；
- 重写 H1；
- 补充视频简介；
- 修改 Tags；
- 自动迁移整棵历史目录；
- 合并重复 BVID；
- 删除测试版本。

需要这些操作时，应作为独立任务处理。
