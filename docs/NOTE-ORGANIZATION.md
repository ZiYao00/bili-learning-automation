# 笔记整理与归档教程

> 文档类型：**操作教程 + 分类说明**。只在用户主动要求整理已有笔记时使用。

新生成的 B站笔记默认只进入：

```text
00-待整理/
```

项目不会因为生成完成、打开 Obsidian、更新导航或发现待整理文件而自动归档。**学习后整理默认关闭。**

---

## 1. 什么时候会执行整理

只有用户明确提出类似请求时才进入整理流程：

```text
帮我整理笔记
整理一下最近的笔记
把待整理笔记归档
```

如果用户没有明确范围，Agent 必须先询问：

```text
要只整理最近一篇笔记，还是整理全部待整理笔记？
```

只有明确得到以下两种范围之一后才能执行：

- `latest`：只整理最近一篇；
- `all`：整理全部 `00-待整理` 笔记。

如果用户在原请求中已经明确说“最近一篇”或“全部”，无需重复询问。

没有明确范围时，不允许预先改名、移动文件、修改 tags 或调用 organizer。

---

## 2. 整理一篇笔记会修改什么

整理前，Agent 需要完整阅读该笔记，再确定四项内容：

| 项目 | 用途 |
| --- | --- |
| 短标题 | 作为整理后的文件名和 H1，快速说明核心知识 |
| 一句简介 | 用一句话概括该笔记长期检索时最重要的内容 |
| 唯一主分类 | 决定笔记存放目录 |
| Tags | 记录模型、工具、技术点、用途等多维信息 |

Organizer 会统一完成：

```text
保留原视频标题
→ 更新短标题 / H1
→ 更新 tags
→ 安全移动到目标目录
→ 防止同名覆盖
→ 重建导航
```

不要手工使用文件管理器、`Move-Item` 或其它方式绕过 organizer。

---

## 3. 短标题怎么写

文件名 / H1 的目标是回答：

> **“这篇笔记核心讲什么？”**

推荐结构：

```text
核心对象 + 核心任务 / 知识点 + 必要区别
```

例如：

```text
原视频：天塌了！真人短剧要变天了! MiniMax H3 9宫格实测 支持无限宫格扩展……
整理后：MiniMax H3 九宫格分镜与角色参考

原视频：综合最优解！2.5 倍的速度提升！SLA 节点 + Comfy Kitchen Attention……
整理后：MiniMax H3 SLA + CK Attention 加速
```

通常删除：

```text
重磅
天塌了
喂饭级
保姆级
真正强大在哪
让你彻底放飞自我
必看
```

但保留模型名、插件名、关键技术、版本和真正影响检索的区别。

整理后，原 B站视频标题不会消失。Organizer 会在标题下方保留：

```text
原视频标题：<原始标题>
```

## 4. 分类的基本原则

分类目录回答：

> **“以后我会去哪个知识区域找它？”**

Tags 回答：

> **“它涉及哪些模型、工具和技术？”**

因此不要把每一个技术点都继续拆成目录。

例如一篇 MiniMax H3 显存教程：

```text
目录：01-视频生成/01-MiniMax-H3
Tags：MiniMax-H3 / 显存优化 / INT8 / KJNodes
```

而不是：

```text
01-视频生成/MiniMax-H3/显存优化/KJNodes/INT8/
```

---

## 5. 视频生成：模型生态优先

视频生成教程通常围绕某个模型生态持续扩展，因此优先按模型 / 模型家族分类。

```text
01-视频生成/
├─ 01-MiniMax-H3/
├─ 02-Wan系列/
├─ 03-Seedance/
├─ 04-其他模型/
└─ 90-进阶专题/
```

### MiniMax H3

所有明确以 MiniMax H3 为底座的教程都集中到：

```text
01-视频生成/01-MiniMax-H3/
```

包括：

```text
显存优化
SLA / Attention 加速
首尾帧
分段长视频
九宫格
数字人
音色替换
节点
LoRA
综合工作流
```

这些技术点通过 Tags 区分，不继续创建 H3 子目录。

### Wan 系列

以下生态统一进入：

```text
01-视频生成/02-Wan系列/
```

例如：

```text
Wan2.1
Wan2.2
SCAIL-2
Wan-Animate-2 / Animate2
```

具体底座版本、衍生模型和动作技术写入标题与 Tags。

### Seedance

Seedance 相关教程集中到：

```text
01-视频生成/03-Seedance/
```

暂时不按 2.0 / 2.1 / 3.0 继续拆目录；版本使用 Tags 和标题区分。

### 进阶专题

```text
01-视频生成/90-进阶专题/
```

只用于**真正不属于单一模型生态**的内容，例如：

```text
视频模型选型
H3 vs Wan vs Seedance 对比
量化格式通用原理
跨模型 Attention / 显存优化原理
首尾帧控制机制的跨模型比较
```

只要一篇教程明显针对某个模型，就仍跟模型走，不因为内容“很进阶”而放进这里。

## 6. 其它领域

当前允许的正式分类以 `config/bilibili-note-taxonomy.json` 的 `organization.categories` 为准。

主要结构：

```text
02-图像生成/
├─ 01-提示词/
├─ 02-图生图与编辑/
├─ 03-控制与一致性/
├─ 04-放大修复/
├─ 05-模型与LoRA/
└─ 99-综合/

03-LLM与智能体/
├─ 01-本地模型/
├─ 02-Coding与Agent/
├─ 03-提示词与系统指令/
└─ 99-综合/

04-写作与内容创作/
└─ 01-AI写作/

98-测试与Benchmark/
```

`98-测试与Benchmark` 用于同视频不同 Agent / 模型、A/B 输出和质量测试，不与正式知识主版本混在一起。

## 7. Organizer 命令

普通用户通常不需要手工执行。Agent 在范围确认后调用：

```powershell
bili-learning organize `
  --note '<现有笔记路径>' `
  --title '<短标题>' `
  --intro '<一句简介摘要>' `
  --category '<taxonomy 目标目录>' `
  --tag '<标签1>' `
  --tag '<标签2>' `
  --confirmed-scope '<latest|all>'
```

`--confirmed-scope` 是强制安全门禁。没有用户明确选择范围，命令不会执行。

`--category` 和至少一个 `--tag` 也是必填项，避免旧流程根据不完整 Tags 自动猜目录。

---

## 8. 批量整理时的处理方式

当用户选择 `all` 时：

1. 只处理 `00-待整理` 内的正式 Markdown 笔记；
2. 每篇完整阅读后独立确定标题、分类与 Tags；
3. 不使用“同一个模型全部套同一标题模板”的批处理方式；
4. 单篇失败时保留该文件和现场，不用手工移动绕过；
5. 所有成功操作都必须经过 organizer；
6. 导航由 organizer 自动刷新。

分类规则本身可以复用，但**笔记内容判断不能只根据旧文件名或旧 Tags**。
