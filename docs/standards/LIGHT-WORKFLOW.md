# 轻量笔记工作流

适用于 `job.json` 中：

```json
"workflow_mode": "light"
```

目标很简单：**完整读字幕，写成真正有用的学习笔记，再单独做一次排版优化。**

## 执行顺序

1. 按 `transcript-manifest.json` 的顺序完整读取全部 transcript chunk。
2. 判断字幕与 UP 主简介是否足以支撑可信笔记；不足时停止，不凭常识补具体事实。
3. 直接写完整笔记，不先填写 Fact Ledger、Semantic Draft 或 Layout Plan。
4. 内容写完后，再独立做一次版式优化。
5. 最后回看字幕，修正明显遗漏和无来源内容，再完成 coverage review。

## 写作目标

把视频转成一篇适合长期学习、检索和实际操作的 Obsidian 笔记。目标不是“把视频压短”，而是让读者在不重看完整视频的情况下，仍能理解其中真正值得长期保留的知识。

优先保留真正有用的信息，例如：

- 参数、数值、数量、上限和下限；
- 工具、模型、节点、插件、版本和资源；
- 操作步骤、前置条件、适用场景和兼容性；
- A/B 差异、作者明确建议和取舍；
- 配置、耗时、质量变化和失败表现等实测结果。

来源只要提供了足够信息，就不要只留下类别名或一句结论；应自然保留对象之间的关系、选择条件、原因、实测证据、失败表现和作者判断。没有这些信息时不要为了补齐结构自行推断。

不要预设章节数量、文章字数、KB 大小或压缩比，也不要为了“简洁”主动压缩有长期参考价值的内容。章节、表格和列表由当前视频的信息关系自然决定；篇幅只由来源中的有效知识量决定，不作为完成或质量达标标准。

## 事实保真

对模型名、插件名、作者 ID、版本号、参数、数字、单位和路径保持保守。视频字幕本身可能来自音频转文字，专有名词出现错字并不等于该知识没有价值；处理不确定专名时按以下三级原则执行：

- **来源可确认**：字幕上下文或 UP 主简介能明确确认时，使用可确认的标准写法；
- **高度疑似但无法确认**：保留有检索价值的内容，并明确写成“字幕原音：`xxx`”“名称未确认”或“待核实”，不得根据模型记忆静默修正为某个看起来合理的正式名称；
- **无法判断**：如果作用、关系或实测结果仍然有价值，保留这些可确认信息，但省略具体拼写；不要为了补齐名称而猜测。

不要仅因为一个专名受损，就删除与它绑定的参数、用途、兼容关系或实测结论；同样也不要把低置信名称升级成无条件确定事实。

如果来源自身前后矛盾，例如分类上限相加与口头总数不一致，应显式保留冲突，不要静默选择其中一个，也不要自行修正来源。

最终回看 transcript 时，优先检查：重大知识模块是否漏掉；成员之间的来源、兼容、互斥和选择关系是否被压平；实测是否保留了条件、结果与失败现象；专名、数字和单位是否被模型自行改写；低置信专名是否被错误升级成确定名称。

## 先看结论与知识关系提炼

“先看结论”只写读者真正需要快速知道的**结论、选择、关键参数、限制、风险和适用场景**。不要使用“本文覆盖……”“本笔记包含……”“接下来介绍……”这类目录式或元描述式摘要，也不要在这里复述完整正文。

正文在完整保留来源事实、参数、比较和实测证据后，可以额外提炼少量有长期价值的**能力边界、因果关系或选择原则**。这种提炼必须能由当前字幕与简介中的多条事实共同支持，例如把两个实测结果概括成“中文理解 ≠ 中文文字渲染”一类关系；它只能作为增量解释，不能代替、删除或改写支撑它的原始条件与证据，也不能引入来源之外的新知识。

## 排版

先确保内容完整，再考虑视觉表达。只有进入这一阶段后，才可按需读取 `docs/OBSIDIAN-STYLING.md`；需要确认某个组件的 Markdown 写法时，只查看 `STANDARD-VIDEO-NOTE-EXAMPLE.md` 中相关的局部片段，不读取严格工作流来重新规划正文。

可以按需要使用：

- 普通段落、列表和步骤；
- Markdown 表格；
- Grid / Card；
- Risk / Meta / Resource；
- Chip / Metric。

当来源明确介绍一组并列对象（例如 `Top N`、项目 / 工具 / Skill / 模型清单）时，默认按来源出现顺序使用连续编号 `01 → N`，概览表与详细标题复用同一编号，不因后续主题归类或能力关系分析打乱主序列。对象存在来源明确提供的外部 URL 时，概览表和详细标题中的对象名称应直接使用 Markdown 超链接；没有明确 URL 时保持纯文本，不自行猜链接。对象之间的能力链、分类或对比可以另用 Callout / Table 提炼，但只能作为补充关系层，不能替代或重排连续编号正文。

没有任何组件是必需的。只有内容关系确实适合时才使用；不要为了美化而删减、改写或重复知识。关闭 CSS 后仍应可读。

不要在正文末尾追加“来源提供的资源”“本笔记不自行补写”等固定收尾说明。来源约束由系统内部执行；只有当某个“三连 / 充电 / 付费 / 外部领取”等条件会改变读者下一步行动时，才在笔记中保留对应资源提示。

## 只保留这些硬边界

- 正文事实只来自当前字幕和 UP 主简介；
- 不修改程序生成的 Frontmatter、H1、元信息、播放器、来源区、资源链接、文件名、路径、tags、cssclasses 和 marker；
- 不覆盖已有笔记；
- 不把 Cookie、runtime 路径、日志或内部状态写进正式笔记；
- 最终仍由 finalizer 校验、发布并清理临时任务。

轻量模式不要求读取或执行 `KNOWLEDGE-DENSE-WORKFLOW.md`，除非用户明确要求切换到 `strict` 模式。
