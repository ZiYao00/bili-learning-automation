# Codex：视频学习笔记生成规范

## 目标

以后生成 B站学习笔记时，请以同目录的：

`STANDARD-VIDEO-NOTE-EXAMPLE.md`

作为**最终成品格式的标准参考**。

这份样例不是“建议之一”，而是默认输出风格。可以根据视频内容适度增减正文细节，但不要重新设计一套更复杂的笔记结构。

## 核心原则

生成的是**给人快速阅读和实践的 Obsidian 笔记**，不是教材、研究报告或机器分析报告。

默认目标：

- 30 秒内判断视频讲什么、是否值得继续看；
- 3 分钟内掌握主要操作方法；
- 需要时可以直接在 Obsidian 内播放原视频；
- 机器需要的字幕、索引、JSON 等资料可以保存，但不要堆到主阅读页面。

## Frontmatter

默认只保留：

- `author`
- `published`
- `duration`
- `source`
- `tags`

不要自行加入大量状态字段、内部任务字段或抓取技术字段，除非以后另有明确要求。

`source` 使用规范化后的 B站原视频 URL，不保留微信分享 URL 中的大量追踪参数。

## 视频简介：硬性必填

**视频简介是高优先级核心内容，不可忽略。**

要求：

1. 必须主动获取 Bilibili 视频信息中的原始简介（通常对应 `desc`）。
2. 必须放在一级标题之后、视频播放器之前。
3. 必须尽量保留 UP 主原始文字，而不是用 AI 摘要替代。
4. 简介中的 URL 应尽可能整理成可点击 Markdown 链接。
5. 简介中的 GitHub、网盘、模型、工作流、文档等资源尤其不能丢。
6. 不要把“字幕里没有提到”当作省略简介的理由；简介来自视频元数据，不是字幕。
7. 如果简介抓取失败：
   - 明确报告抓取失败；
   - 不得悄悄省略；
   - 不得虚构；
   - 当前笔记应视为“资料不完整”，等待补抓。

如果视频确实没有简介，才允许写：

`> 本视频未提供简介。`

“接口暂时没抓到”不等于“视频没有简介”。

## 视频播放

默认优先使用 Obsidian 原生支持的 HTML `iframe`，嵌入 Bilibili 官方播放器。

这条方案不要求安装额外插件，也不要求下载视频。

播放器应使用规范化 `bvid`，不要把手机分享链接的跟踪参数直接塞入 iframe。

如果当前 Obsidian 环境无法正常显示 B站 iframe，再单独评估插件方案。不要为了理论上的兼容性预先安装插件。

如确实需要插件：

- 先说明原生 iframe 失败的具体原因；
- 推荐范围应尽量小；
- 未经用户明确同意，不自动安装插件；
- 当前项目不处理本地视频嵌入，本地视频方案以后再讨论。

## 正文结构

默认尽量压平层级。

推荐保持：

- `# 视频标题`
- 视频简介
- 视频播放器
- “先看结论” Callout
- `## 怎么做`
- `## 容易踩坑`
- 必要时在“容易踩坑”后加入简短实践清单

不要默认生成以下内容：

- 知识地图
- 核心概念卡
- 多层章节树
- 自测题
- 证据脚注列表
- 来源覆盖与局限
- 机器资料清单
- 重复的来源信息
- 重复的作者/时长/标签展示行

只有视频本身确实复杂，或者用户明确要求“深学”，才增加更深结构。

## 时间点链接

字幕中有明确关键位置时，可在“怎么做”下面提供少量时间点链接。

要求：

- 链接文字必须让人一眼看懂内容；
- 使用如 `02:34 末帧桥接` 的形式；
- 不要在正文展示机器内部的 `P01@...`、JSONL ID 等证据编号。

## 机器资料

完整字幕、metadata、证据索引等文件可以继续保存，方便 Agent 后续检索。

但默认不要在主笔记底部展示：

- “资料来源”
- “机器资料”
- JSONL 索引
- 抓取状态
- 是否下载音频/视频等内部执行信息

这些属于 Agent/系统层，不属于人的主阅读层。

## 内容质量

不要为了填满模板而重复同一信息。

尤其注意：

- “先看结论”和“怎么做”不能只是换一种说法重复；
- 实践清单只保留真正值得用户动手验证的步骤；
- 视频很短时，正文也应相应更短；
- 不确定的资源地址、节点名称和事实不要猜测；
- 原始资料没有支持的内容应明确说明，而不是补全想象。

## 完成判断

一篇默认视频学习笔记至少应满足：

- Frontmatter 五项已填写；
- 视频原始简介已填写，或确认视频确实无简介；
- B站播放器已正确嵌入；
- 一句话/短段结论能说明视频价值；
- 主要操作步骤清楚；
- 主要坑点清楚；
- 链接可点击；
- 主页面没有机器噪音和不必要层级。

以后优先对照标准样例调整内容，不要每次重新设计格式。
