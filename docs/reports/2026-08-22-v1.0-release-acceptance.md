> [!important] 基线验收记录，已被同日后续修复部分取代

## Clean-room 验收

在仓库的 Git-ignored `.runtime/release-acceptance/` 下创建隔离克隆与测试 Vault，不复用维护者的正式 Obsidian 笔记目录。

### 1. 干净克隆初始状态

新克隆没有 `config/local.json`、Cookie 或私人笔记。

首次 doctor 正确报告：

- Python、项目根和 taxonomy 可用；
- `notes_repository_fallback`；
- `obsidian_vault_unknown`；
- `ytdlp_not_configured`；
- Cookie 文件缺失。

缺失 yt-dlp 时只提供：

```powershell
winget install yt-dlp
```

没有自动下载、自动安装或向 Skill 内复制 `yt-dlp.exe`。

### 2. Vault 首次绑定

通过正式配置入口把隔离 Vault 写入 clean clone 的 `config/local.json`：

```powershell
python .\hermes-skills\bili-learning-automation\scripts\configure_bilibili_learning.py --vault '<test-vault>' --notes-subdir 'bilibili'
```

返回 `status = configured`。

将仓库中的：

```text
obsidian/snippets/learning-lab.css
obsidian/snippets/video-note.css
```

复制到测试 Vault 的 `.obsidian/snippets/` 后，doctor 能正确识别两份 CSS。

### 3. 配置完成后的 doctor

在隔离克隆中配置有效 yt-dlp 与 Cookie **文件路径**后，doctor 返回：

```text
status = ok
warnings = 0
```

Cookie 内容在验收过程中没有被读取或写入报告。

## Agent 写作与 Finalizer

按照 `agent_handoff.md` 和共享内容标准：

1. 判断字幕与简介为 `sufficient`；
2. 建立 `knowledge_outline`；
3. 只填写 `BILI_AI_SUMMARY` 与 `BILI_AI_BODY`；
4. 重新对照 transcript 完成 coverage review；
5. 调用正式 finalizer。

Finalizer 返回：

```text
status: note_ready
temporary_data_removed: true
```

发布后的 Markdown 已确认：

- 保留 author / published / duration / source / tags；
- 包含 `learning-page + video-note`；
- H1 下方为“作者 · 日期 · 时长 · BVID”元信息；
- 阅读顺序为“先看结论 → 知识正文 → 视频资料”；
- 条件资料获取提示来自简介 / 字幕，不生成未采集到的资料本体；
- `BILI_AI_*` runtime marker 已移除；
- runtime job 已清理。

## 重复转换与失败路径

同一个 BV 在首篇笔记完成后再次执行 collector，目标文件自动变为：

```text
原视频标题（2）.md
```

没有覆盖已有笔记。

随后故意不填写第二个任务的 AI 区域直接运行 finalizer，得到：

```text
status: note_invalid
temporary_data_removed: true
```

因此确认：

- 不完整草稿不能进入正式笔记库；
- 失败任务仍会通过 finalizer 安全清理；
- 重复转换与并发保护不是永久去重。
